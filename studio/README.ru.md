# AI-Figma — установка на сервер

Редактор интерфейсов в браузере, устроенный как Figma (фреймы, автолейаут, компоненты и варианты, стили,
переменные, прототипы), со встроенным помощником на вашей локальной модели и файлами на вашем сервере.
На сервере нужны только **nginx + PHP + Ollama** — то, что у вас уже есть. Ничего компилировать не нужно.
Редактор полностью автономный: всё загружается из его папки, интернет и сторонние сайты не нужны.

## Установка (5 минут)

1. **Скачайте готовую сборку.** GitHub → репозиторий `ai-figma` → справа **Releases** →
   верхняя «Сборка N — дата» (с пометкой Latest) → файл `ai-figma-build-N-ГГГГ-ММ-ДД.zip`.
   У каждой сборки свой номер и описание «что нового» (то же — в `CHANGES.ru.md`).
   Какая сборка стоит у вас, видно в шапке панели помощника: «Модель: … · сборка N».
2. **Распакуйте** — внутри одна папка `ai-figma`.
3. **Положите её на сервер** рядом с остальными приложениями: `/app/src/ai-figma/`.
   Папку можно назвать как угодно и переименовать потом — все пути внутри относительные.
   Помощник и хранилище файлов сами найдут ваш `auth.php` на два уровня выше (`/app/src/auth.php`)
   и через него — `config.php`, `.env`, адрес Ollama и модель.
4. **Папка для файлов пользователей создаётся сама**: `storage/ai-figma` рядом с корнем сайта
   (на сервере с корнем `/app/src` это `/app/storage/ai-figma`, то есть на диске `/var/www/dwr/storage/ai-figma`).
   Она вне корня сайта, поэтому снаружи файлы не скачать, а при обновлении приложения они не трогаются.
   Проверка: откройте `https://ваш-домен/ai-figma/api/files.php` — должно быть `{"ok":true,…}`.
   Если там ошибка «Не удалось создать папку», создайте её сами и дайте PHP право записи
   (`sudo mkdir -p /var/www/dwr/storage/ai-figma && sudo chown 33:33 /var/www/dwr/storage/ai-figma`; 33 — www-data в контейнере PHP)
   или укажите другое место в `.env`: `AI_FIGMA_DATA_DIR`.
5. **nginx** — помощнику нужны большие запросы (снимок экрана) и долгое ожидание модели, сохранению —
   большие файлы: готовые блоки в `nginx.conf.example` (правила не зависят от имени папки).
   Если у сервера эти значения уже больше (например, `client_max_body_size 999M` на весь сервер), ничего менять не нужно.
   Для больших макетов с картинками проверьте и PHP: `post_max_size` не меньше размера файла.
6. **Откройте** `https://ваш-домен/ai-figma/` — войдите в систему, если ещё не вошли.
   Справа появится панель «Помощник», в её шапке — значок папки «Мои файлы».

Обновление — то же самое: скачать новый zip и заменить папку. Свой `studio/config.js`
перед заменой лучше сохранить.

## Файлы

- **Ctrl+S** (или «Файл › Сохранить») сохраняет открытый файл в «Мои файлы» на сервере. Первый раз
  спросит имя; дальше сохраняет туда же. «Сохранить как» — копия под новым именем.
- **Мои файлы** — значок папки в шапке панели помощника: список файлов с датой и размером, поиск,
  открыть, переименовать, удалить (удалённое уходит в корзину `.trash` на сервере), новый файл,
  «С компьютера…» — открыть `.figcraft`, `.fig` (с ограничениями), SVG или картинку.
- У каждого пользователя своя папка: файлы видит только тот, кто их сохранил.
- **Автосохранение:** файл, который уже лежит на сервере, сохраняется сам раз в минуту, если в нём
  есть изменения (`autosaveSeconds` в `studio/config.js`). Кроме того, браузер каждые 30 секунд держит
  несохранённую копию: если вкладка закрылась без сохранения, при следующем открытии панель предложит
  её восстановить. Перед закрытием вкладки с несохранёнными изменениями браузер переспросит.
- Экспорт картинок и PDF — как в Figma: панель «Экспорт» справа у выделенного слоя; файлы скачиваются в браузере.

## Что внутри папки

| Путь | Что это |
|---|---|
| `index.html`, `index.php` | Страница редактора (`index.php` отдаёт её без кэша) |
| `app/` | Сам редактор (WebAssembly, сжат и разрезан на части) |
| `studio/loader.js` | Показывает ход загрузки и, если что-то не так, какой файл не пришёл и почему |
| `studio/` | Панель помощника и «Мои файлы»: `studio.js`, `studio.css`, `ru-labels.json`, `version.json` |
| `studio/config.js` | **Настройки панели** — можно править прямо на сервере |
| `api/assistant.php` | Помощник: проверяет вход, отправляет запрос в Ollama |
| `api/files.php` | Файлы пользователей на сервере |
| `api/settings.php`, `api/tools.php` | Внутренние настройки и список действий помощника |

## Настройки в `.env` (необязательно)

По умолчанию всё берётся из вашей системы. Переопределить можно так:

| Переменная | Что делает | По умолчанию |
|---|---|---|
| `AI_FIGMA_DATA_DIR` | Где хранить файлы пользователей | `storage/ai-figma` рядом с корнем сайта (`/app/storage/ai-figma`) |
| `AI_FIGMA_MODEL` | Модель помощника (нужны картинки и tools) | `GLOBAL_MODEL` |
| `AI_FIGMA_OLLAMA_URL` | Адрес Ollama или шлюза | `OLLAMA_IP:OLLAMA_PORT` |
| `AI_FIGMA_CONTEXT` | Размер контекста | `GLOBAL_MODEL_CONTEXT` или 32768 |
| `AI_FIGMA_TIMEOUT` | Сколько секунд ждать модель | 180 |
| `AI_FIGMA_MAX_TOKENS` | Длина ответа | 2048 |
| `AI_FIGMA_AUTH_FILE` | Путь к `auth.php`, если папка лежит не в `/app/src/` | ищется автоматически |
| `AI_FIGMA_ALLOW_ANON` | `1` — без входа (только для проверки!) | выключено |

Запросы помечаются для шлюза как `ai-figma` через ваш `enrichLLMPayload()`.

## Шаблоны и быстрые задачи

- **Шаблоны** — значок с квадратиками в шапке панели помощника (или кнопка «Шаблоны и быстрые задачи»
  в пустой панели). 53 шаблона по группам: элементы, карточки, навигация, экраны телефона, блоки сайта,
  соцсети и печать. Сверху — поиск, цвет и светлый/тёмный вариант. Нажмите на шаблон — он появится на холсте
  справа от остального, выделенный; Ctrl+Z убирает его целиком. Тексты меняются двойным щелчком.
- **Быстрые задачи** — вторая вкладка там же: действия в одно нажатие (автолейаут, выравнивание, тень,
  компонент, прототип, экспорт) и готовые просьбы помощнику.
- Помощник пользуется теми же шаблонами («вставь экран входа») и собирает новые макеты по описанию целиком.

## Как работает помощник

- **Совет** — объясняет, где найти функцию и что выставить. Ничего не меняет.
- **Сделай** — сам собирает и меняет макет: создаёт фреймы, текст и фигуры, включает автолейаут,
  выставляет отступы, цвета, скругления и тени, делает компоненты, выравнивает, связывает экраны в прототип,
  смотрит на результат. Каждое действие видно в ленте, у каждого есть кнопка «Отменить»; всё отменяется и Ctrl+Z.
  Закрытие файла, удаление страниц и стилей — только после вашего «Разрешить».
- **Быстрая строка — Ctrl+Shift+Пробел** (или кнопка-молния в шапке панели): поле внизу над холстом,
  ответ всплывает над ним, вся история — в панели.
- **Глаз** рядом с полем ввода — показывать ли помощнику экран (снимок уходит только на ваш сервер).
- **Палитра** в шапке панели — тема: Фирменная, Светлая, Тёмная. То же — «Вид › Тема» и настройки редактора.
- «Справка» в меню редактора открывает панель помощника.
- Пока модель думает, сервер помощника раз в 10 секунд отправляет пустой пробел, чтобы роутер,
  VPN или прокси не оборвали «молчащее» соединение.

## Если что-то не работает

| Признак | Что проверить |
|---|---|
| Редактор не запускается | Под полосой загрузки написано, какой файл не пришёл и почему. Чаще всего: папка скопирована не целиком, или правило сервера отдаёт вместо файлов другую страницу |
| После заливки по FTP — старая версия или «Не удалось скачать app/loader…» | Программа заливки пропустила файлы «того же размера» (так умеет FileZilla). С этой сборки размер таких файлов меняется в каждой сборке, но надёжнее в FileZilla выбрать для существующих файлов «Перезаписать», а не «Перезаписать, если размер отличается» |
| В панели «Нужно войти в систему» | Вход в вашу систему в этом же браузере и на этом же домене |
| «Не найден auth.php системы» | Задайте `AI_FIGMA_AUTH_FILE` в `.env` |
| «Не удалось создать папку для файлов» | Создайте `storage/ai-figma` рядом с корнем сайта и дайте PHP право записи, или задайте `AI_FIGMA_DATA_DIR` |
| «Сервер не передал PHP содержимое файла» | Файл больше `post_max_size` в PHP — увеличьте `post_max_size` |
| «Сервер помощника ответил не JSON» | PHP не обрабатывает файлы в папке `api/` — проверьте блок PHP в nginx |
| Ошибка 413 | `client_max_body_size` (пункт 5) |
| Ошибка 504 / ответ обрывается | `fastcgi_read_timeout 200s` (пункт 5) |
| «Модель не умеет вызывать инструменты» | `AI_FIGMA_MODEL` с поддержкой tools |
| «Модель не принимает картинки» | Выключите «глаз» или укажите мультимодальную модель |

Проверка без панели: `https://ваш-домен/ai-figma/api/assistant.php` должно показать `{"ok":true,"model":"…"}`,
а `https://ваш-домен/ai-figma/api/files.php` — `{"ok":true,"files":[…]}`.

## Дальше

Совместная работа нескольких пользователей в одном файле (как в Figma) — следующий этап: у исходного
проекта есть свой сервер совместной работы, его можно будет подключить внутри вашего контура.

## Для разработчика

- Сборку делает GitHub Actions (`.github/workflows/studio.yml`) на каждое изменение ветки `main`.
- Мост редактора: `apps/figcraft-web/src/bridge.rs` — `window.aifigma.request(метод, параметры)`,
  те же методы, что у канала управления (`crates/ui-egui/src/control.rs`). В консоли браузера:
  `await aifigma.execute('shape.rectangle', {x: 0, y: 0, width: 100, height: 50})`.
- Сохранение на сервер: команды `file.pageSnapshot` и `file.pageSaved`; Ctrl+S приходит в страницу событием `aifigma:save`.
- Темы: `Tokens::brand()` в `crates/ui-egui/src/theme.rs`, команда `view.themeBrand`.
- Панель: `studio/web/`, сервер помощника и файлов: `studio/api/`.
